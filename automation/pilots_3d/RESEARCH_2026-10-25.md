# BuiltWhys 3D Shorts research — 2026-10-25

This note records evidence for the lock pilot only. The user's pasted planning
document was treated as design input, not as authorization to modify the live
producer, scheduler, publisher, social accounts, or server.

## Reference observations

- The supplied 96.8-second local MP4 uses dark backgrounds, white/orange short
  headlines, a centered animated mechanical diagram, highlighted components,
  changing camera/framing, and bottom subtitles. It is mainly clean schematic
  2D/2.5D—not an example of a fully photoreal 3D render in every shot.
- The linked Instagram reel could not be inspected: public-page fetching failed
  and the local browser access was unavailable. Do not claim visual details of
  that reel based on its URL alone.
- The original BuiltWhys lock pilot had a generic T-shaped front and detached
  looking pieces. The second pilot replaces those with a recognizable inset
  keyway, escutcheon, key bitting, cylindrical cutaway, pin chambers, springs,
  rotating face, cam, and sliding bolt. It remains an illustrative model, not
  measured manufacturer CAD.

## Relevant repositories

| Project | Actual approach | Fit for our existing Ubuntu/CPU pipeline |
| --- | --- | --- |
| [BBN Video Studio](https://github.com/Boom-Vitt/bbn-video-studio) | Short explainer workflow joins headless Blender EEVEE plates, three.js overlays, local TTS, captions, SFX and scene-level review. | Closest visual-production reference, but its published setup requires an Apple Silicon Mac and substantial model storage/token work. Architectural ideas only; not a drop-in server install. |
| [vsim](https://github.com/kunalkushwaha/vsim) | Validated scene/film documents feed deterministic 3D + 2D rendering, with headless frame capture and FFmpeg output. | Strong pattern for structured scene plans and repeatable renders. Young project; adoption would require validation and benchmarking. |
| [MotionCraft](https://github.com/ahmdd4vd/MotionCraft) | Remotion templates, timing, sound and exported-frame/phone-size QA. | Useful composition and QA ideas; it does not supply a faithful lock model. |
| [AutoBroll](https://github.com/andriidrok1/autobroll) | Edits supplied clips using Remotion, WhisperX timing and B-roll. | Useful for caption/timeline concepts, not for building correct new 3D mechanisms. |
| [Remotion](https://github.com/remotion-dev/remotion) | Programmatic React composition and headless render. | Potential later compositor, but adds Chromium/Node and has license conditions; FFmpeg already meets the pilot's composition needs. |

The pilot deliberately does not copy the reference's footage, voice, text,
diagram assets, logo or music. No third-party model was imported. Any future
asset-library entry must record the source and commercial-use license.

## Rollout boundary

The second lock pilot is still local and review-only. A production version
needs a validated mechanical-template catalog, original English narration,
voice/animation cue alignment, visual QA on final MP4 frames, a bounded CPU/RAM
render worker, scene-level retry/cache, and a feature flag preserving the old
pipeline. Benchmark on the actual server before enabling automatic publication.
